1. 뽑기 결과의 예상 가치와 판매 완료 손익은 다릅니다

손익 계산기는 원더베리·로얄스타일·플래티넘 애플에 사용한 메소와 판매 완료한 결과물의 실수령액을 비교합니다. 결과물을 얻었다는 사실만으로 판매 수입을 기록하지 않습니다. 각 결과물의 판매 여부에서 판매를 선택해야 그 줄의 가격·개수·수수료가 수익 계산에 들어갑니다. 아직 팔지 않은 아이템에 예상 판매가를 입력해도 판매를 선택하지 않았다면 수익은 0입니다.

3억 메소를 사용하고 예상 판매가 5억인 결과물을 보유 중이라면 판매 완료 기준 손익은 −3억입니다. 보유 아이템의 가치가 없다는 뜻이 아니라, 실제 판매 수입이 없다는 뜻입니다. 보유품의 현재 가치나 미래 기대수익과 구분해서 읽어야 합니다.

거래 예제의 구입·판매 가격과 수량·수수료는 설명용 가정값이며 현재 시세, 획득 확률, 미래 수익을 뜻하지 않습니다. 소울·고급 어빌리티의 기본 강화 단가는 아래에 공식 근거를 따로 표시했습니다. 무료 지급품이나 다른 방식으로 얻은 재료에 임의의 시장가격을 붙여 지출에 넣으면 실제 지출과 가상 평가가 섞이므로 주의하세요.

2. 상품별 계산기는 투입 비용과 판매 실수령을 분리합니다

원더베리의 투입 항목에는 위습의 원더베리와 루나 크리스탈, 로얄스타일에는 로얄스타일과 프리미엄 마스터피스가 있습니다. 사용한 항목의 개당 가격과 개수를 각각 입력합니다. 플래티넘 애플은 애플의 개당 가격과 개수로 기본 지출을 계산합니다. 비용은 개당 가격 × 개수를 항목별로 더한 값입니다.

가령 원더베리 2억과 루나 크리스탈 1억을 사용하고 결과물을 총 3억 5,000만에 판매했다면, 수수료 3%의 실수령은 3억 3,950만입니다. 손익은 339,500,000 − 300,000,000 = 39,500,000메소입니다. 계산기의 지출에 루나 크리스탈을 빠뜨리면 이익이 1억 더 크게 보이므로, 마지막으로 산 재료만 적지 않았는지 확인해야 합니다.

3. 구입한 날과 판매한 날이 다르면 기록도 나눌 수 있습니다

현재 손익 기록에는 날짜가 하나 있습니다. 같은 기록 안에서 비용은 8월 31일, 판매 수입은 9월 2일처럼 서로 다른 날짜를 지정하지는 않습니다. 날짜별 메소 흐름을 관리하려면 구입일에 비용 기록을 저장하고, 나중에 판매한 날에는 비용을 다시 넣지 않은 판매 수입 기록을 추가하는 방법을 사용할 수 있습니다.

8월 31일 원더베리에 3억을 사용하고, 9월 2일 결과물을 3억 5,000만에 팔아 수수료 3%가 적용됐다고 가정합니다. 8월 31일 기록은 비용 3억, 판매 미체크로 저장합니다. 9월 2일에는 원더베리 계산기를 다시 열고 날짜를 맞춘 뒤 비용 항목은 비워 두고, 실제 판매한 결과물의 개수·개당 판매가·수수료를 입력해 판매를 선택합니다. 이 수입 전용 기록도 저장할 수 있습니다.

현재 저장된 손익 목록은 삭제 기능을 제공하며, 기존 기록을 다시 여는 편집 기능은 제공하지 않습니다. 나중에 판매 상태를 업데이트하려고 무작정 동일 기록을 새로 저장하지 마세요. 비용 없는 판매 기록으로 이어 적거나, 수정이 꼭 필요하면 먼저 백업과 원래 입력 내용을 보관한 뒤 중복 없이 다시 구성해야 합니다. 서로 연결된 거래라는 메모는 별도로 남겨 두면 좋습니다.

4. 일부만 팔았거나 판매가가 다르면 줄 단위를 살펴보세요

결과물 한 줄에는 가격 하나, 개수 하나, 판매 체크 하나가 있습니다. 예를 들어 같은 등급의 펫 3개 중 1개만 판매했는데 개수 3을 적고 판매를 선택하면 3개 모두 판매한 것으로 계산됩니다. 판매 수입을 추가할 때는 실제로 판 개수만 넣으세요. 아직 보유 중인 2개를 판매 수익에 포함하지 않는 것이 우선입니다.

같은 등급의 결과물 두 개를 각각 1억과 1억 4,000만에 팔았고 수수료 3%를 가정하면, 각각의 실수령은 9,700만과 1억 3,580만, 합계 2억 3,280만입니다. 판매일이나 가격이 다르면 비용 없는 판매 기록을 따로 저장하면 각 거래를 확인하기 쉽습니다. 평균 단가 1억 2,000만과 개수 2를 넣어도 이 예제의 합계는 같지만 개별 거래 가격을 추적하기는 어렵습니다.

수수료는 결과물 줄마다 선택하며 손익 판매 화면은 3%와 5%를 제공합니다. 한 줄에 입력하는 것은 개당 판매가입니다. 2개를 합쳐 2억 4,000만에 팔았는데 개당 가격에 2억 4,000만, 개수에 2를 넣으면 판매 총액이 두 배가 됩니다. 수량 1개와 총액으로 기록했다면 그 기록을 아이템 개수 집계에도 사용할 수 있는지 별도로 판단해야 합니다.

한 결과물을 합성·사용하여 다른 결과물을 얻었다면 중간 아이템의 예상 판매가를 수익으로 넣지 않습니다. 실제로 사용한 재료의 비용과 최종 판매 수입을 연결해 검산하세요. 같은 비용을 손익 계산기와 지출 기록 양쪽에 넣는 것도 피해야 합니다. 손익 계산기의 비용은 이미 통계 손익에서 차감되므로 직접 지출에 또 적을 필요가 없습니다.

5. 강화 API의 추정 비용은 확인 후 지출로 확정합니다

강화 메뉴는 스타포스 · 잠재능력 · 소울 에테르 · 고급 어빌리티 · 직접 입력 탭으로 모여 있습니다. 잠재능력 탭에서 메소 재설정과 큐브 사용 이력을 함께 확인하며, 두 종류의 금액은 따로 표시합니다. 소울·고급 어빌리티는 현재 직접 입력하는 방식입니다.

지출 기록의 강화 이력은 사용 횟수와 조건을 모아 비용을 추정하는 기능입니다. 메소 사용액 (추정)에 숫자가 표시되거나 이력을 불러왔다는 사실만으로 전부 확정 지출이 되는 것은 아닙니다. 상세 내역 · 비용 조정에서 조건을 확인하고 최종 반영 금액 (메소)을 정한 뒤 지출 반영을 눌러 확인한 항목이 통계에 들어갑니다.

추정 1억 2,000만이 표시됐지만 실제 사용 메소를 따로 확인해 보니 1억 500만이었다고 가정합니다. 이때는 추정치의 근거를 확인하고 최종 반영 금액을 105,000,000으로 설정하여 확정합니다. 확정 후 장부에 들어가는 지출은 1억 500만이며, 추정 1억 2,000만을 추가로 또 차감하는 방식이 아닙니다. 확인 전 이력과 확인 후 지출을 나누어 볼 수 있어야 숫자의 의미가 분명해집니다.

잠재능력의 이력당 재설정이 실제 사용 방식과 다른지도 확인하세요. 1회 비용을 가상으로 400만, 이력 10개로 두면 1회 설정일 때는 4,000만입니다. 실제로 각 이력에 3회 재설정을 사용했다면 같은 단가 가정에서 총 30회, 1억 2,000만입니다. 이는 횟수 차이를 보여 주는 산술 예제이며 실제 장비의 재설정 단가를 뜻하지 않습니다.

큐브 환산액 · 지출 아님은 특히 구별해야 합니다. 무료로 받은 큐브 10개를 사용했고 화면 환산액이 8,000만이어도 실제 메소를 지출하지 않았다면 8,000만을 지출로 확정할 근거가 되지 않습니다. 화면도 실제 메소 지출임을 확인하는 체크를 요구합니다. 사용량을 메소 기준으로 환산한 숫자와 실제 메소 구매액은 서로 다른 정보입니다.

장비 레벨·단가가 미확인이거나 이력이 누락되면 추정액도 불완전할 수 있습니다. 실제 비용을 알 수 없는 이력은 임의의 시세로 확정하지 말고 확인할 대상으로 남겨 두세요.

6. 수동 지출·API 확정·손익 비용은 같은 거래를 한 번만 반영합니다

스타포스·잠재능력·주문서·추가옵션·어빌리티 비용을 직접 적으려면 강화 지출 직접 입력을 사용합니다. 이미 수동으로 적은 같은 강화 비용을 API 이력에서 다시 확정하면 중복될 수 있습니다. 같은 날 수동 기록이 있으면 화면은 별개 비용인지 확인하도록 요구하지만, 그 체크만으로 두 지출이 실제로 다른 거래라는 사실을 사이트가 증명하는 것은 아닙니다.

예를 들어 하루 재획과 보스로 얻은 수입이 5억, 원더베리 실현 손익이 +3,950만, 직접 구매 지출이 6,000만, 별개의 API 확정 강화 지출이 1억 500만이라면 최종 순수익은 500,000,000 + 39,500,000 − 60,000,000 − 105,000,000 = 374,500,000메소입니다. 원더베리 원가 3억은 이미 +3,950만을 구할 때 차감했으므로 여기에서 다시 빼지 않습니다.

API 원본 이력의 중복 수집과 중복 확정은 식별자를 기준으로 보호하지만, 사람이 다른 제목으로 적은 모든 수동 거래를 자동으로 매칭하지는 못합니다. 검산할 때는 같은 날짜·캐릭터·장비·강화 종류·금액이 반복되는지 확인하고 실제로 다른 비용인지 구분하세요. 동일한 날에 별개 강화 작업을 했을 수도 있으므로 금액이 같다는 이유만으로 삭제해서는 안 됩니다.

확정 / 제외한 강화 이력에서 확정 내역을 확인할 수 있습니다. 지출이 아니라고 판단한 이력은 제외로 관리하며, 확정한 금액을 취소할 때는 반영 취소를 사용합니다. 이 동작은 API 원본 이력을 남기면서 지출 반영 상태를 바꾸는 기능입니다. 제외한 이력은 다시 조회했다고 자동으로 지출에 추가되지 않습니다.

월말에는 판매 날짜, 미판매 결과물, 중복 비용, 미확정 이력을 확인하고 JSON 백업을 보관하세요. 손익 계산기는 뽑기 거래를 자동 수집하거나 구매·판매 기록을 자동 연결하지 않습니다. 사용자가 거래 근거를 남겨야 판매 지연과 실제 비용 증가를 구분할 수 있습니다.

7. 소울·고급 어빌리티는 실제 시도 횟수로 비용을 검산합니다

위 계산기는 공식 기본 단가 × 실제 횟수 + 실제 재료 구입비로 사용 메소를 계산합니다. 강화에 성공했는지와 관계없이 지불한 횟수를 입력합니다. 아래 표는 2026년 9월 17일 본서버 기본 비용이며 9월 19일 재확인했습니다. 소울 증폭·잠재 등급이 바뀌거나 어빌리티 잠금 수가 달라지면 구간별로 나눠 계산합니다.

계산 예제는 1단계 증폭 3회, 레어 잠재 재설정 2회, 잠금 2개인 어빌리티 10회를 가정합니다. 에테르 2,000만·훈장 500만이라는 구입 단가와 각 3개의 구입 수량은 가상값이며 실제 시세나 필요한 재료 개수를 뜻하지 않습니다. 성공까지의 기대 비용, 목표 옵션 등장 가능성, 증폭 게이지는 계산하지 않습니다.

고급 어빌리티 예제에서는 명성치도 40,000 × 10 = 400,000 소모합니다. 이미 가진 명성치를 사용하고 훈장을 사지 않았다면 메소 지출은 1억 5,000만입니다. 소모한 명성치 40만을 메소 비용에 더하지 않습니다. 훈장을 3개 샀다는 가정은 명성치 40만을 훈장 3개로 모두 충당했다는 의미가 아닙니다. 명성치 잔액과 실제 훈장 구입 내역은 각각 확인하세요.

재료를 구입한 날에 이미 구매 지출로 저장했다면, 나중에 재료를 사용한 날에는 같은 구입비를 다시 적지 않습니다. 재료를 쓰면서 추가로 소모한 메소만 새로 기록합니다. 반대로 한 기록으로 묶어 정리할 때는 다른 구매 기록과 겹치지 않는지 확인해야 합니다. 현재 이 두 탭은 API 자동 수집을 하지 않으므로 수기 기록의 날짜·이름·단가·수량을 남기는 것이 기준입니다.

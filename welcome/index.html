재획과 조각

사냥할 때 환산한 조각을 팔면 수익을 또 더할까요?

조각을 이미 메소로 환산한 회차와 나중의 판매 정산을 모두 수입에 넣으면 같은 조각이 두 번 계산됩니다. 회차에 고정한 조각 가격, 보유 수량, 실제 판매 원본을 나누어 살펴봅니다.

조각 수입의 중복 반영 예제
보스와 파티 분배

판매가를 인원수로 나누었는데 왜 내 몫이 다를까요?

판매 수수료를 뺀 금액과 파티원에게 송금한 뒤의 실수령액은 다릅니다. 파티장·파티원 비율과 송금 수수료, 100메소 단위 내림까지 조건을 바꿔 확인합니다.

조건별 파티 분배 계산
판매와 강화 지출

보유 아이템의 가격과 가져온 강화 이력은 확정 금액일까요?

팔지 않은 아이템의 예상 가격은 확정 수입이 아닙니다. API로 가져온 강화 이력도 실제 조건과 금액을 확인한 뒤 지출에 반영합니다. 수기 비용과 같은 거래인지 확인하는 과정이 필요합니다.

제작과 기록 기준

누가, 어떤 기준으로 만들었나요?

메이플스토리 크로아 월드의 얀보가 개인 기록용으로 시작한 비공식 도구입니다. 다른 메모장에 흩어진 재획·보스·지출 기록을 모으고, 같은 거래가 중복으로 더해지지 않도록 만드는 데 목적을 둡니다.

제작 목적과 운영 방식

사용 과정에서 바꾼 것

  • 결정석 판매 시점 구분

    점검 전에 판매한 이용자의 금액이 패치 후 가격으로 섞이지 않도록 시점을 구분했습니다.

  • 조회 방식의 중복 요구 수정

    넥슨 로그인 후 개인 API 키를 또 요구한다는 제보를 반영해 연결 경로를 정리했습니다.

  • 종료된 상품의 기록 보존

    기간 한정 상품의 신규 입력이 끝나도 기존 손익과 지출 기록은 남기는 기준을 사용합니다.

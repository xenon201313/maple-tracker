# 월말 예상 기록 순수익 계산 기준

수정일: 2026-11-05

## 고친 문제

기존에는 이번 달 순수익 전체에 `월 일수 ÷ 경과일`을 곱했다. 예를 들어 10월 5일에 주간·월간 보스 등으로 기록한 32,329,755,368 메소를 `31 ÷ 5`배 해 200,444,483,281 메소로 표시했다. 매일 반복하지 않는 수입과 지출까지 같은 비율로 늘린 것이 원인이다.

## 현재 산식

`오늘까지 기록한 순수익 + 최근 반복 수입 합계 × 내일부터 월말까지 남은 일수 ÷ 표본 달력 일수`

- 현재 기록 순수익에는 기존 보고서에 포함되는 수입과 지출을 한 번만 반영한다. 미래 날짜·주차의 기록은 예상의 현재 합계에서 제외한다.
- 반복 수입 표본은 오늘을 제외한 최근 최대 14일이다. 재획 회차의 메소와 판매로 기록한 일간 결정석만 사용한다.
- 조각 판매 정산·환산액, 기타 수입, 복구 보정, 보스 드랍, 주간·월간 보스, 손익 계산기 판매액과 직접 지출을 추가 예상에 반복 적용하지 않는다. 이미 기록된 금액은 현재 합계에 남는다.
- 기록을 시작한 뒤 완료된 기간이 7일 이상이고, 재획 또는 일간 판매가 기록된 날이 3일 이상일 때 계산한다. 쉬는 날도 분모에 포함한다. 자료가 부족하면 현재 금액과 함께 ‘예측 대기’를 표시한다.
- 오늘은 부분 기록일 수 있으므로 평균 표본에서 제외하고, 추가 예상도 내일부터 계산한다. 월말 당일·지난달은 기록 금액을 그대로 표시한다. 미래월은 예측하지 않는다.
- 금액과 비율 연산은 `BigInt` 정수 계산을 사용한다. 저장된 장부와 API 원본은 변경하지 않는다.

이 값은 미래 지출·보스·일시 판매까지 예측한 최종 결산이나 실제 보유 메소가 아니다. 화면에도 추가 예상에 포함되는 항목과 제외되는 항목을 안내한다.

## 날짜와 기존 월 귀속

예상 기준일은 한국 시간으로 계산한다. 해외 시간대에서 월경계에 접속해도 예상 영역은 한국 시간의 월간 보고서를 선택한다. 날짜 간격과 월말·윤년 계산은 UTC 날짜 단위로 처리해 기기의 서머타임 영향을 받지 않는다.

기존 `todayStr()`와 다른 기록·보고서 화면은 여전히 브라우저의 현지 날짜를 사용한다. 이 수정은 전체 장부 날짜를 강제로 바꾸거나 과거 기록을 옮기지 않는다. 또한 주간 보스의 월별 보고서 귀속은 기존 `weeksForDashboardMonth()` 기준을 유지한다. 예상 계산에서 미래 기록을 제외하기 위한 조회만 추가했다.

격리된 Chrome의 합성 장부로 실제 월간 보고서와 연결해 검증한다. 미래 재획·손익·지출·주간/월간 결정석·드랍과 월말 주차에 포함된 다음달 일간 기록이 예상의 현재 합계에서 빠지는지, 원본과 저장소가 그대로 남는지 확인한다. 한국과 미국 시간대에서 한국 시간 월경계의 보고서 선택도 확인한다.
